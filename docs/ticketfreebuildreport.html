código pronto
O que é

Site que lê o Postgres e mostra cards (imagem, nome, data, link) de eventos no RJ que são grátis ou custam até R$20. Um robô roda a cada 6h, abre a página de eventos da Sympla num navegador headless, clica nos filtros de preço do próprio site, e grava o que encontra no banco.

Fonte 1 de N — nasceu como spec pra 5 sites (Ingresse, Ingresso.com, Sympla, Eventbrite, Even3/Bileto), mas virou MVP com só a Sympla depois de pesquisa ao vivo mostrar que reverse-engenheirar 5 APIs não documentadas de uma vez ia gerar código quebrado. Sympla prova a pipeline inteira; as outras 4 entram uma a uma depois, cada uma verificada contra o site real antes de codar.

Como foi construído

Processo formal, não vibe coding: brainstorming → spec (docs/superpowers/specs/2026-09-05-ticket-free-design.md) → plano de implementação (docs/superpowers/plans/2026-09-05-ticket-free-mvp.md) → execução por subagentes. Cada uma das 9 tasks do plano foi implementada por um agente fresco, revisada por um segundo agente (spec + qualidade de código), e só marcada como pronta depois do veredito limpo. No fim, uma revisão de branch inteira (modelo mais forte) caçou o que a visão por-task não pega.

Revisão final de branch inteira

Feita num modelo mais forte, olhando as 9 tasks juntas. Achou 4 bugs reais que uma visão por-task não pegaria — todos já corrigidos numa rodada única de fix + re-revisão, sem regressão:

⚠ precisa rodar contra a Sympla real pra corrigir direito

A revisão final achou 3 bugs prováveis no scraper, mas nenhum foi corrigido no código agora — corrigir sem ver o DOM real da Sympla é repetir o erro que este projeto já evitou uma vez (adivinhar API em vez de verificar ao vivo). Ficam pra corrigir assim que a primeira varredura real rodar.

  1. Clique pode falhar por ambiguidade"Grátis" provavelmente aparece tanto no filtro quanto no preço de cada card — Playwright pode recusar clicar em texto ambíguo.
  2. Preço pode vir erradoO parser lê a página inteira; pode pegar valor de parcela ou taxa de serviço em vez do preço real do ingresso.
  3. Filtro "Grátis" pode não ser desmarcado antes de aplicar "Pago"Se for multi-seleção, a segunda passada reconta eventos grátis como candidatos pagos.
